# ダミーデータで画面を作って見えたこと

画面は `src/` にダミーデータで実装した。ダミーデータは `db/dummy.ts` にあり、`npm run db:seed` で DB に入れる。画面は `src/data/index.ts` の関数を通して DB を読む。

## ページごとに必要なデータ

| ページ | 最低限必要 | あると良い | 取得の見通し |
|---|---|---|---|
| お知らせ | 見出し、公開日時、原文 URL | 要約、分類 | 市公式の RSS やお知らせ一覧で足りる見込み。分類は公式の区分か LLM で付ける |
| イベント | 名称、開催日時、会場名、原文 URL | 位置、地区、料金、主催、分類 | 位置と地区はページに載らないことが多く、会場名や住所から補う必要がある |
| 開店・閉店 | 店名、種類（開店・閉店など）、情報源 URL | 実施日、地区、既存の店との紐付け | 網羅できる情報源はなく、半手動になる |
| マップとスポット | 名称、種類、位置 | 住所、営業状況、種類ごとの属性 | 避難所は国土地理院の指定緊急避難場所・指定避難所データ。公共施設、公園は国土数値情報。店舗は OpenStreetMap と手入力 |
| 地区ガイド | 地区名、概要文 | 境界、人口 | 概要文は手書き。境界は e-Stat |
| 歴史 | 年表の本文 | 写真、古地図 | 手書き。写真は出典とライセンスの管理が要る |
| 交通 | 路線と駅の説明 | 時刻 | 公共交通オープンデータセンターに立川分があるかは要確認 |
| 統計 | 人口、世帯、年齢構成 | 推移 | e-Stat から年次で取得 |

## 設計上の論点

- 会場の正規化: 同じ会場が複数のイベントに現れる（ダミーでも駅前広場とこもれび公園が 2 回ずつ出る）。会場を places に登録し、events から参照する形（events に `place_id` を追加）にすると、位置と地区を会場側で一度だけ持てる
- 位置情報がなくても成立する作り: 位置が NULL のイベントも、一覧とカードには表示される（詳細ページの地図だけ出ない）。段階 1 は位置なしで始め、会場が登録されるにつれて埋める
- 開店・閉店は、日付や店の特定ができない場合を前提にする: 実施日が NULL なら「時期未定」と表示し、未登録の店は店名だけで載せる
- お知らせは原文を保存しなくても画面が成り立つ: 見出し、日付、URL が取れれば足りる。要約は LLM で作れるが、必須ではない
- 分類は必須にしない: 取れなければ「お知らせ」にまとめる
- 歴史、交通、統計は更新が少ない: DB ではなく Markdown や JSON を git で管理する方が扱いやすい
- 取得に失敗している間は古い情報が出続けるため、情報源ごとの最終取得日時と状態を画面に出している

## 画面側で許容している欠損

位置、地区、料金、主催者、分類、実施日、営業状況は、取れなくても表示が崩れない。中止と延期は status で表示を切り替える。

## 市公式サイトの RSS（2026/11/02 に確認）

- RSS 2.0 で、サイト全体の新着が 1 本にまとまっている。直近 1 か月分、200 件あまりが載る
- 項目は見出し、URL、公開日時。概要はほとんど空
- 分類の項目はない。URL の最初の階層（bosai、kurashi、kosodate など）で分類を決める
- イベントのページ（event 階層）も含まれる
- 規約では文章と画像の無断転載を禁じ、リンクはトップページへ張るよう求めている。見出し、公開日時、URL だけを掲載する

## 国土地理院の指定緊急避難場所・指定避難所データ（2026/11/02 に確認）

- 市町村ごとに、指定緊急避難場所と指定避難所の 2 つの CSV（GeoJSON も同梱）を配布している。ダウンロードは画面操作が必要で、URL での自動取得はできない
- 項目は名称、住所、緯度経度、指定緊急避難場所の対象とする災害の種類。収容人数はない
- 両方の CSV に載る施設は、共通 ID の末尾 3 桁以外が同じ
- 立川市分は指定避難所 43 件、指定緊急避難場所 46 件。広域避難場所 3 件は指定緊急避難場所だけに載る
- 第三者に提供する場合は、最新でない場合があること、指定緊急避難場所は災害の種類ごとに指定されること、随時更新されることを伝えるよう求めている
